# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The primary audience is HR and hiring managers assessing KBber for technical roles. Engineers reviewing project implementations are also readers. This audience is confirmed by the user's request to communicate technical competence to HR.

## Product Purpose

A personal website presenting software projects, articles, notes, photos and an about page. Visitors can understand what a project does and follow its GitHub link to inspect the implementation.

## Operating Context

The existing site uses Astro, TypeScript and some React islands. It is hosted at https://kbber.github.io/ with GitHub Pages. The local source is this repository.

## Capabilities and Constraints

Preserve project facts, repository links and the existing article, note, photo and about routes. Project descriptions must be supported by source material. The user wants natural wording and technical specificity.

The redesign is attended. Present examples first, obtain the user's choice, then confirm homepage composition, project presentation and interaction details in sequence. Publish only after the user approves the completed result.

## Brand Commitments

Use the public account name KBber. Omit real personal names. The user selected the kinetic-sand-glyphs direction: matte black and deep umber with antique gold and warm ochre. The homepage composition, material assets and first viewport have been accepted.

## Evidence on Hand

src/data/projects.ts contains the current project inventory and repository links. src/content/ contains existing articles, notes, moments and album records. Project implementations and documentation are in the user's local workspaces and public GitHub repositories. No new performance, employment, customer or business claims are authorized.

## Product Principles

- Explain each project through its function and implementation.
- Let visitors inspect the work through demos and repository links.
- Keep real personal names out of public presentation.
- Ask for the user's visual approval before implementation.
